Pipeline

Récapitulatif : les règles de la stratégie

Trunk-based development : un seul tronc, main, dans lequel on ne merge que du code testé et prêt pour la prod. Les versions sont des tags, et une branche release n'existe que si on en a besoin.

Branches

  • main : protégée, prochaine version de prod. Merger = prêt pour la prod, donc on part en prod rapidement.
  • feature/*, bugfix/*, hotfix/* : courtes, créées depuis main, squash merge (un commit = un revert possible).
  • Pas de branche develop, ni de branches qui suivent les environnements.
  • Gros développement : découper en morceaux livrables, ou feature flag désactivé par défaut.
  • release/x.y : seulement si main ≠ prod. Créée depuis le tag de la version en prod, cherry-picks venant de main uniquement, supprimée quand la version suivante est stable.

Tests et environnements

  • Sandbox (optionnelle) : développer sans bloquer personne.
  • DEV : main automatiquement, et réservation (verrou) pour valider une branche avant le merge. Règles : branche à jour depuis main, durée limitée, merge aussitôt, retour automatique à main, messages Kafka compatibles.
  • QUALITÉ : tags -rc.N. PROD : tags finaux, après approbation.
  • Construire une fois, déployer partout : la même image va de QUALITÉ à PROD.

Tags, images et Kafka

  • DEV : pas de tag (app:main-<commit>). rc : créé par le pipeline à l'entrée en QUALITÉ. Final : créé après l'approbation, sur le même commit que le dernier rc, avant le déploiement.
  • Tags protégés : jamais déplacés ni réutilisés. Les rc restent dans Git (journal).
  • Registre : images main 30 j, rc 60 à 90 j, versions finales jamais supprimées.
  • Rollback = redéployer l'image précédente, sans toucher à Git.
  • Kafka : topics préfixés en sandbox ; une branche en DEV remplace le pod avec les mêmes consumer groups.
⛔ À éviter : une branche develop ou qa permanente · plusieurs branches déployées en même temps en DEV · corriger sur release sans reporter dans main · déplacer ou réutiliser un tag · recompiler entre QUALITÉ et PROD · reset ou push forcé sur main (utiliser git revert).

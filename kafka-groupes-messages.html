Kafka — Gestion des groupes de messages · FIFO, DLQ & topic de reprise

Récapitulatif

Deux mécanismes complémentaires pour traiter des groupes de messages dans Kafka en garantissant l'ordre.

① Routage du groupe vers une partition dédiée

  • Clé du message = identifiant du groupe → hash(clé) % nb_partitions.
  • Tous les messages d'un groupe vont dans la même partition, dans l'ordre d'envoi.
  • Une partition n'est lue que par une seule instance du groupe de consommateurs : FIFO garanti par groupe.
  • Les groupes sont traités en parallèle. Avec une partition dédiée par groupe, on a au plus autant de groupes que de partitions.

② Gestion d'erreur : DLQ + topic de reprise

  • En cas d'erreur, la partition est suspendue et le message reste bloqué (offset non commité).
  • Une copie est envoyée dans la DLQ, dans la même partition d'origine (P1 → D1), avec l'offset et la cause de l'erreur.
  • L'utilisateur corrige le message et le republie dans le topic de reprise, dans la même partition (D1 → R1).
  • Le topic de reprise est consommé en priorité. Ensuite, le message d'origine est ignoré grâce au registre des messages déjà traités, et la partition est débloquée.
✅ Ordre final du groupe B : B1 → B2′ → B3 → B4. Le FIFO est respecté et les groupes A et C n'ont jamais été bloqués.
Points d'attention : la DLQ et le topic de reprise doivent avoir le même nombre de partitions que le topic principal · le registre d'idempotence doit être persistant · surveiller la durée de suspension d'une partition (alertes) · prévoir le cas « message non corrigeable » (ignorer explicitement).

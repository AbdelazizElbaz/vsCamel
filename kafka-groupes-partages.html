Kafka — Groupes partagés sur les partitions · FIFO, DLQ & topic de reprise

Récapitulatif — groupes partagés sur les partitions

Plusieurs groupes de messages partagent la même partition. Le FIFO reste garanti par groupe, mais une erreur bloque toute la partition.

Routage partagé

  • Clé = identifiant du groupe → hash(clé) % nb_partitions. Plusieurs groupes tombent dans la même partition (A et D → P0, etc.).
  • L'ordre est garanti pour chaque groupe, car tous ses messages sont dans la même partition.
  • Avantage : le nombre de groupes n'est plus limité par le nombre de partitions.

Conséquence en cas d'erreur

  • L'erreur sur B2 suspend toute la partition P1. Le groupe E est bloqué aussi, même s'il n'a aucune erreur.
  • Le message est copié dans la DLQ, dans la même partition (P1 → D1), et l'utilisateur le corrige. B2′ est republié dans R1 (D1 → R1) et consommé en priorité.
  • B2 est ignoré grâce au registre, puis P1 reprend : les groupes B et E sont débloqués ensemble.
✅ Ordre traité par C2 : B1 → E1 → B2′ → E2 → B3 → E3. Le FIFO est respecté pour B (B1 → B2′ → B3) et pour E (E1 → E2 → E3).
Compromis : plus de groupes possibles, mais une erreur bloque tous les groupes qui partagent la partition. Plus il y a de partitions, plus ce blocage reste localisé. Une correction rapide est d'autant plus importante.
